# budget_bot — личный трекер бюджета

## Что делает проект
Telegram-бот для быстрого ввода трат/доходов (1-2 действия) + полноценный сайт (не Mini App)
с входом через Telegram Login Widget. Решает проблему заброшенных прошлых попыток вести
бюджет (Excel, самодельный бот): забывчивость закрывает вечернее напоминание, неудобство —
быстрый ввод, отсутствие плана — лимиты по категориям, отсутствие наглядности — сайт-дашборд.

Полный архитектурный план: `C:\Users\Maki4\.claude\plans\distributed-pondering-eclipse.md`.

## Статус реализации
- **Фаза 1 (бот, MVP) — готово**: быстрый ввод (оба порядка + задним числом), категории,
  лимиты (`/limit Категория 0` — снять), `/day` с удалением записей, вечернее напоминание,
  whitelist-админка, подсказки команд (setMyCommands).
- **Фаза 2 (сайт) — готово**: `auth.py` (Telegram Login Widget + Fernet session-cookie),
  `/api/*` (summary, transactions с PATCH/DELETE, categories, limits), `web/` —
  Дашборд (KPI-плитки, бары по категориям, метры лимитов), История (фильтр, смена
  категории, удаление), Лимиты. Vue 3 через CDN, светлая/тёмная тема.
- **Аналитика — готово**: сравнение с прошлым месяцем (плитки + категории), топ-5 трат,
  график по дням (7/14 дней/месяц, парные столбики расходы+доходы), прогноз расходов до
  конца месяца, предупреждения по лимитам через бота (ежедневно 12:00 МСК, один раз за
  месяц на категорию, таблица `limit_alerts`). «Разовые» траты (⚡, `is_oneoff`) не
  экстраполируются в прогнозах; порог подсказки настраивается (вкладка ⚙️).
- **Умные лимиты — готово**: `smartlimits.py` (nice_round, suggest, шаг ±10%),
  `budgets.mode` ('manual'|'auto'). Автоподбор на сайте (предпросмотр с галочками →
  режим auto), пересчёт 1-го числа 9:00 МСК (`bot/auto_limits.py`) по темпу за 90 дней
  без разовых; пока учёту < 45 дней — без ограничения шага. Ручное изменение всегда
  переводит в manual. Отложено пользователем: «остаток на день» — вернуться позже.
  **Пересчёт пропускается, если за последние 30 дней меньше 5 трат**
  (`smartlimits.MIN_ACTIVITY_TX`): месяц без записей означает «не вёл учёт», а не
  «стал тратить меньше». Без этой проверки лимиты усыхали на 10% за каждый месяц
  простоя и встречали вернувшегося ложными предупреждениями о превышении.
- **Дизайн — «Швейцарская сетка»** (выбор пользователя из трёх прототипов): рамки без
  теней, капительные ярлыки, светлая тема базовая + ручной переключатель 🌙 (localStorage).
  Пользователь не хочет «нейросетевой» вид (градиенты/стекло/неон).
- **ИИ-советник — готово**: `ai.py` — клиент к любому OpenAI-совместимому API
  (по умолчанию OpenRouter с бесплатной моделью; переменные `AI_API_KEY`, `AI_BASE_URL`,
  `AI_MODEL`; без ключа всё тихо отключается). Две функции:
  1) **Автокатегоризация** при быстром вводе: сначала таблица `category_memory`
     (запомненные выборы пользователя, фраза целиком → отдельные слова), затем ИИ;
     запись сохраняется сразу, кнопка «🔁 Изменить категорию» (`chg:`/`chgc:`)
     исправляет и переучивает память. Без совпадений — прежняя клавиатура категорий.
  2) **Месячный разбор** (`bot/ai_review.py`): `/review` — текущий месяц,
     `/review прошлый`; автоматически 1-го числа в 9:30 МСК за закончившийся месяц.
     Модель получает только агрегаты из БД (итоги, категории с прошлым месяцем,
     топ трат, лимиты) — не сырые данные и не прямой доступ к БД.
- **Фаза 3 (цели накопления) — готово**: `goals`/`goal_contributions` — виртуальная
  копилка: пополнение НЕ создаёт transaction и не влияет на расходы/лимиты/прогнозы.
  Накопленная сумма = `SUM(goal_contributions)` (без отдельного `current_amount`).
  Бот (`bot/goals.py`): кнопка «Цели» / `/goals` — список с юникод-прогрессбаром и
  темпом «₽/мес» при заданном сроке, инлайн «➕ Пополнить» на цель → готовые суммы
  или свободный ввод (`context.user_data["pending_goal"]`, проверяется в `route_text`
  до быстрого ввода трат); `/goal Название Сумма [ДД.ММ.ГГГГ]` — создать/обновить,
  `/goal Название 0` — удалить. Сайт: вкладка «Цели» (`/api/goals` GET/POST/PATCH/
  DELETE + `/api/goals/{id}/contribute`) — создание, пополнение/снятие, архив.
  Месячный ИИ-разбор включает блок по целям (сколько отложено за месяц).
- **Пересылка банковских уведомлений — готово**: `bot/bank_notify.py` — регулярки под
  реальные форматы push-уведомлений Сбера (покупка), Ozon Банка (покупка), Альфа-Банка
  (пополнение); пользователь пересылает текст пуша боту, дальше та же автокатегоризация,
  что и у обычного ввода. Другие типы операций пока не распознаются — добавляются по
  мере поступления новых образцов текста от пользователя.
- **Фаза 4 (импорт банковских выписок) — готово**:
  `parsers/` (ABC `BankStatementParser` + `ParsedTransaction` в base.py, реестр в
  `__init__.py`, `dedup.py` — sha256-хэш строки), `bot/imports.py` — приём файла →
  выбор банка (инлайн) → `parser.parse()` → дедуп (совпадение по сумме ±1 день:
  0 кандидатов → новая запись с автокатегоризацией; 1 ручная → помечается сверенной
  выпиской, не дублируется; 1 импортированная → пропуск; несколько → очередь ручного
  уточнения в `context.chat_data["import_review"]`). Таблица `import_batches` — сводка
  каждой загрузки.
  **Дедуп переделан 08.09.2026** — старый терял операции (на реальной выписке Ozon
  23 строки из 261 на 241 617 ₽). Правила теперь такие:
  1) `import_hash` уже в БД → операция импортирована раньше, пропуск;
  2) ровно одна ручная **не сверенная** запись с той же суммой в ±1 день → сверка,
     хэш пишется на неё же (иначе повторный импорт создал бы её заново);
  3) таких ручных записей несколько → очередь уточнения;
  4) иначе новая запись.
  Импортированные записи кандидатами на сверку НЕ являются: иначе две одинаковые
  покупки за день схлопываются в одну. Их различает `import_hash`, который строится
  по `external_id` (колонка «Документ» выписки) **вместе с датой и суммой**, а при
  отсутствии номера — по времени с точностью до секунды. По дате без времени
  строить нельзя — теряются повторы. Одного номера операции тоже мало, и это
  видно на реальных выписках: у внутренних операций Ozon номер короткий и сквозной
  («3», «4», «186»), а Альфа проводит под одним кодом сразу несколько операций
  (погашение долга 66,00 и процентов по нему 0,08 — оба TIRR#26062001875 за 27.08).
  Дата и сумма у одной операции не меняются, поэтому повторный импорт того же
  файла по-прежнему даёт тот же хэш.

  **Все три парсера написаны по реальным выпискам пользователя (14.09.2026).**
  Форматы разные, и это важно:

  | банк | дата | знак | дробная часть | ключ операции |
  |---|---|---|---|---|
  | Ozon | дата+время | `+`/`-` у обоих | точка | «Документ» |
  | Сбер | дата+время | `+` у дохода, у расхода нет | запятая | дата+код авторизации |
  | Альфа | только дата | `-` у расхода, у дохода нет | запятая | дата+код операции |

  У Сбера операция занимает ДВЕ строки: шапка с суммой, затем описание.
  У Альфы внутри описания встречаются суммы с точкой («на сумму: 83.00 RUR»),
  от колонки суммы их отличает запятая; строки HOLD (неподтверждённые) пропускаются.
  Код авторизации Сбера сам по себе не уникален, поэтому external_id = дата+код:
  без этого три поездки CITYDRIVE по 48,89 в одну минуту схлопнулись бы в одну.

  **Разбор идёт по вёрстке, а не по плоскому тексту (правка 14.09.2026).**
  Первая версия писалась по пересказу выписки, где операция была одной строкой,
  и на настоящих PDF развалилась: в `extract_text()` длинное назначение платежа
  рвётся на несколько строк, а сумма остаётся в первой. От описания оставался
  обрывок («Оплата товаров по»), и переводы себе переставали опознаваться —
  на выписке Ozon из 378 операций распозналось 0 вместо 124.
  * **Ozon** — `page.extract_tables()`: пять колонок, описание приходит целиком.
    Если сумма в строке не читается, парсер бросает исключение, а не пропускает
    строку: молчаливая потеря операций опаснее отказа разобрать файл.
  * **Альфа** — по координатам слов (`parsers/layout.py`). Продолжение описания
    начинается ровно с левого края своей колонки (x≈188), а подпись
    уполномоченного лица — с другой (x≈388). Приклеивать подряд нельзя: в подписи
    стоит ФИО владельца, и комиссия сошла бы за перевод самому себе. Без склейки
    терялся хвост номера телефона («+7 (996) 593-36-» + «13» на следующей строке)
    и СБП-перевод себе не распознавался.
  * **Сбер** — разбор по тексту, он сходится с итогами банка как есть.

  **Эталон для проверки — итоги, которые банк печатает сам** (`Итого зачислений`
  у Ozon, `Пополнение/Списание` у Сбера, `Поступления/Расходы` у Альфы).
  На выписках за 01.08–14.09.2026 сходится до копейки: Ozon 378 операций
  (1 012 732.74 / 1 010 668.10), Сбер 258 (821 312.69 / 821 312.89),
  Альфа 26 (40 900.00 / 40 900.00) и 20 (1 131.08 / 1 230.08 − 99.00 HOLD:
  банк считает неподтверждённую операцию расходом, мы ждём настоящей проводки).
  Сами выписки в репозиторий не кладём — это личные документы.
- **Переводы между своими счетами — готово (14.09.2026)**: `transactions.is_transfer`.
  Перевод себе попадает в обе выписки (расходом в одной, доходом в другой) и без
  обработки раздувает месяц с обеих сторон: на реальных данных пользователя это
  было 49% «расходов» и 68% «доходов». Такие записи видны в истории, но исключены
  из `get_totals`, `get_category_breakdown`, `get_daily_totals`, `get_top_expenses`,
  `get_spend_rates`, `get_budget_progress` и `count_expenses_since`.
  Опознаются в парсерах (`parsers/identity.py`):
  Ozon — «Перевод собственных средств» плюс Получатель/Отправитель совпадает
  с «Владелец:» из шапки; Сбер — «Перевод в/из <Банк>» без имени человека и
  «Альфа-банк»; Альфа — «Внутрибанковский перевод между счетами», служебные
  переносы банка и СБП на свой телефон из настройки `users.own_phones`.
  Сравнение имён требует совпадения двух полных слов (инициалы игнорируются),
  иначе однофамилец считался бы своим счётом. Пометку можно снять или поставить
  вручную кнопкой 🔁 в истории на сайте.
- **Отложено пользователем**: «остаток на день» — сколько можно тратить в день,
  чтобы уложиться в лимиты.

## Деплой
Railway, отдельный сервис (аналогично ozz_bot). Репозиторий `maki44444/BudJetBot`,
ветка `main`, авто-деплой по push. Сайт: `SITE_URL` (см. переменные окружения).

**На сервере Python 3.11** (`.python-version`), локально у разработки может стоять
3.12 — и часть синтаксиса 3.12 молча проходит локальную проверку, а на Railway
валит сборку. Так уже случалось (14.09.2026): обратный слэш внутри выражения
f-строки разрешён только с 3.12 (PEP 701), из-за него `parsers/ozonbank.py` не
импортировался, за ним падали `bot/__init__.py` и `main.py` — сервис ушёл в
крэш-луп, бот молчал, сайт отдавал 502.
Важно: `ast.parse(..., feature_version=(3, 11))` такие места **не ловит** —
в 3.12 f-строки разбирает токенизатор, и флаг на них не влияет. Проверять надо
обходом AST: у каждого `FormattedValue` смотреть исходный текст выражения на
обратный слэш и на повторное использование тех же кавычек.

## База данных (PostgreSQL)
Создаётся идемпотентно в `db.py:_create_tables()` (`CREATE TABLE IF NOT EXISTS` +
`ALTER TABLE ADD COLUMN IF NOT EXISTS`, без Alembic).

**Порядок важен: `ALTER TABLE X` обязан идти ПОСЛЕ `CREATE TABLE X`.** На боевой
базе таблицы уже есть и ошибка незаметна, но на пустой `ALTER` падает с
`UndefinedTableError` и приложение не стартует. Так было с `budgets.mode`
(исправлено 08.09.2026). Проверять развёртывание с нуля можно в отдельной схеме:
создать схему, поднять пул с `server_settings={"search_path": ...}`, вызвать
`_create_tables()` + `_seed_default_categories()`, затем `DROP SCHEMA ... CASCADE`.

- `users` — telegram_id, whitelist (`is_allowed`), настройки напоминаний
- `categories` — глобальные дефолтные (`telegram_id IS NULL`) + пользовательские
- `transactions` — расходы/доходы, `source` ('manual'|'import'), `bank`/`raw_description`/
  `import_batch_id`/`import_hash`/`reconciled` — заполняются при импорте выписок
- `budgets` — месячные лимиты по категории
- `no_spend_days` — ручная отметка "сегодня трат не было" (чтобы напоминание не спамило)
- `category_memory` — запомненные фразы→категории для автокатегоризации ввода
- `goals` / `goal_contributions` — цели накопления; накоплено = SUM(contributions),
  пополнение НЕ создаёт transaction (виртуальная копилка, вне статистики расходов)
- `import_batches` — сводка каждой загрузки выписки (банк, файл, счётчики строк)

Данные полностью изолированы по `telegram_id` — не общий семейный бюджет.

## Быстрый ввод трат
Свободный текст `сумма [описание]`: без знака — расход, `+` — доход
(`350 такси`, `+50000 зарплата`). Бот показывает инлайн-клавиатуру категорий,
по тапу транзакция сразу пишется в БД.

## Безопасность
- Whitelist: только пользователи из `users.is_allowed=TRUE` + `ADMIN_ID`
- Только личные чаты (`filters.ChatType.PRIVATE`)
- Сайт использует Telegram Login Widget + Fernet session-cookie (алгоритм подписи
  отличается от Mini App initData — см. `auth.py` и план)
- **`crypto.decrypt()` возвращает `None`, если значение не расшифровалось.**
  Не возвращать исходную строку! Раньше здесь был фолбэк «считать открытым текстом»
  (наследство ozz_bot), и из-за него куку можно было выписать себе самому:
  подделанный открытый JSON `{"uid": ..., "exp": ...}` принимался за валидную сессию
  без знания `ENCRYPTION_KEY`. Исправлено 08.09.2026.
